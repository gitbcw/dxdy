# 小程序 UI 对齐实施清单

> 日期：2026-05-07  
> 目标：先将小程序 UI 对齐客户定稿设计图，再基于业务变更文档逐步补齐功能。  
> 设计图索引：`docs/superpowers/specs/2026-05-07-dxdy-design-image-index.md`  
> 业务变更文档：`docs/superpowers/specs/2026-05-07-dxdy-new-prd-gap-analysis.md`

## 1. 执行原则

- 先 UI，后业务。第一轮重点还原客户确认的页面风格、信息层级、组件形态和角色工作台。
- 先小程序，后后台。当前设计图主要覆盖小程序端客户、代理商、制单员三类角色。
- 先骨架，后真实状态。UI 第一轮允许使用现有 CloudBase 数据、已有字段或前端临时映射，不为了缺字段阻塞视觉落地。
- 不再依赖 `packages/shared` 作为真实业务基准。真实数据和功能以后以项目级 CloudBase 环境 `cloudbase-d4gwpsm7gcc59b6fc` 为准。
- 保留已确认业务能力，尤其是待支付订单后台改价，不在 UI 改造中移除。

## 3. 全局 UI 系统

第一轮先沉淀统一样式，避免每个页面各写一套。

### 3.1 视觉基调

- 背景：浅灰白 `#f7f8f7` 或接近设计图的柔和灰白。
- 主绿色：用于品牌、成功状态、认证通过、导航选中、状态线。
- 强橙色：用于主操作按钮、价格、提交、立即购买、提现等关键动作。
- 辅助蓝色：用于冷链、物流、信息状态。
- 警示红/橙：用于紧急、驳回、售后、异常状态。

### 3.2 通用组件样式

需要优先统一以下组件：

- 顶部页面容器：白底、圆角卡片、轻阴影、合理安全区。
- 表单行：左侧 label + 右侧输入/选择/箭头，细分割线。
- 信息卡片：8-12rpx 圆角、浅阴影、内边距稳定。
- 状态标签：认证、订单、冷链、售后、紧急、待审核、已完成等。
- 主按钮：橙色渐变或纯橙，固定高度，大圆角。
- 次按钮：绿色描边或浅绿底。
- 时间线：订单流程、认证流程、售后进度、物流轨迹。
- 金额展示：价格橙色，收益/提成绿色或橙色强调。
- 底部导航：按角色切换不同 tab 文案和图标。

### 3.3 建议新增样式组织

可先在小程序全局样式中沉淀基础 token：

- `app.wxss`：全局背景、字体、按钮、卡片、状态标签、表单行、时间线基础类。
- 页面 `wxss`：只写页面布局差异。
- 若后续重复明显，再抽组件，不在第一轮过度抽象。
